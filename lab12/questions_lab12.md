# Контрольные вопросы к лабораторной работе №12[cite: 27]

**15. Чем аутентификация отличается от авторизации?**  
Аутентификация проверяет *личность* пользователя (кто вы?), а авторизация определяет его *права и разрешения* (что вам разрешено делать?)[cite: 24].

**16. Что такое JWT и из каких частей он состоит?**  
JWT (JSON Web Token) — это формат токена, состоящий из трех частей, разделенных точкой: `header` (заголовок), `payload` (данные) и `signature` (подпись)[cite: 24].

**17. Шифрует ли JWT содержимое payload?**  
Нет. JWT сам по себе не шифрует данные (они кодируются в Base64), поэтому конфиденциальную информацию передавать в payload нельзя[cite: 24].

**18. Что такое серверная сессия?**  
Механизм хранения состояния сеанса пользователя на стороне сервера, связанный с клиентом посредством защищенного идентификатора (cookie)[cite: 24].

**19. Зачем нужны HttpOnly и Secure для cookie?**  
* `HttpOnly` защищает куки от чтения через JavaScript (защита от XSS)[cite: 24].  
* `Secure` разрешает передачу куки только по защищенному протоколу HTTPS[cite: 24].

**20. Почему localStorage не рекомендуется для хранения чувствительных токенов?**  
Из-за риска кражи токенов при XSS-атаках, так как к `localStorage` имеет доступ любой скрипт на странице[cite: 24].

**21. Чем OAuth 2.0 отличается от OpenID Connect?**  
OAuth 2.0 — это протокол *авторизации*, а OpenID Connect (OIDC) — надстройка над ним для *аутентификации* (входа) пользователей[cite: 24].

**22. Что такое access token и refresh token?**  
* `Access token` — короткоживущий токен доступа к защищенным ресурсам[cite: 24].  
* `Refresh token` — токен для безопасного обновления access token без повторного ввода пароля[cite: 24].

**23. Зачем проверять срок действия JWT?**  
Чтобы ограничить время жизни сеанса и минимизировать риски при компрометации токена[cite: 24].

**24. В чем различие HTTP 401 и 403?**  
* `401 Unauthorized` — пользователь не вошел в систему (нет аутентификации)[cite: 27].  
* `403 Forbidden` — пользователь вошел, но у него нет прав на этот ресурс (нет авторизации)[cite: 27].

**25. Почему нельзя полагаться только на скрытие кнопки в интерфейсе?**  
Скрытие элементов на клиенте не защищает бэкенд; злоумышленник может сделать прямой запрос к API, поэтому проверка прав должна выполняться на сервере[cite: 24].

**26. Что должно происходить при выходе пользователя?**  
Сервер должен уничтожить сессию, а клиент — удалить токен авторизации и перенаправить пользователя на форму входа[cite: 24].
